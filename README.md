# refaceCS
Manager for the Yamaha refaceCS Synthesizer 

## v0.10 highlights — 2026-11-16

The Settings dialog configures dark synth appearance, section order and startup state, MIDI-connect behavior, Groove Studio defaults, patch-load protection and audio visibility. Resetting settings preserves saved patches, loops, and patterns. See [#10](https://github.com/sterudo/refaceCS/issues/10).

## v0.8 highlights — 2026-11-16

Contextual help now covers synth controls, Looper, Groove Studio, and Patch Manager. The top Help includes the former bottom-panel playing tips. A centralized, filterable message log has dismissal, error-only reopening, vertical resizing, and pinned top controls. Click **v0.10** for brief dated version history.

Older history was checked against version-introducing commits and issues [#1](https://github.com/sterudo/refaceCS/issues/1)–[#5](https://github.com/sterudo/refaceCS/issues/5). Dates follow those commits; the v0.1 summary includes its subsequent unversioned improvements. This release implements [#6](https://github.com/sterudo/refaceCS/issues/6).

## v0.7 highlights

MIDI Learn maps absolute controller knobs and sliders to on-screen synth faders, with pickup to prevent jumps after patch changes. Assignments are saved per controller, incoming channel and CC in this browser, and can be cleared individually. The controls beneath the synth share a compact, aligned toolbar; Modulation value now sends standard CC 1, replacing the old wheel-target selector. See [issue #5](https://github.com/sterudo/refaceCS/issues/5).

## v0.6 highlights

Groove Studio can send drums to a separate hardware or virtual MIDI output, with internal, external or combined routing; CS2x kit/Performance presets; editable note mappings and octave shifts; lane velocity levels; and external reverb. The arpeggiator now shares Groove Studio's beat grid, and optional start-on-keypress follows transport linking. Combined routing applies the MIDI offset to external drums too; external-only routing keeps internal tone controls out of the way. Routing preferences stay browser-local and existing data remains compatible. See [issue #4](https://github.com/sterudo/refaceCS/issues/4).

## v0.5 highlights

Device settings can be read and edited from a dialog or the synth panel, with MIDI receive-channel-aware routing. Connecting or reconnecting automatically captures the current synth sound after protecting unsaved edits; pitch-bend range follows device readouts and is not restored from browser storage.

## Development

Requires Node.js 20.19+ or 22.12+ (or a newer supported release) and npm.

For this repository, increase the version when starting a new coding session, then keep it unchanged until the next **full deploy**.

```powershell
npm install
npm run dev
```

Open the localhost URL printed by Vite, including `/static/reface/`.
The current page is an interactive SVG panel built with vanilla JavaScript, HTML, and CSS.
It discovers MIDI devices, routes notes, synchronizes documented synth controls, plays synthesized drum grooves, and manages local patch cards with optional MP3 previews.
The surrounding page and toolbar use a dark theme; the synth retains its original light case.

## Deployment

The GitHub Actions workflow deploys the static app to GitHub Pages when changes are pushed to `main`, or when run manually.
Enable GitHub Pages in the repository settings with **Build and deployment → Source: GitHub Actions**.
After the workflow succeeds, the app is available at <https://sterudo.github.io/refaceCS/>.
The Pages build uses `/refaceCS/` as its asset base; local builds continue to use `/static/reface/`.

## Interactive panel

- **Messages** beneath the MIDI controls collects timestamped feedback from MIDI, reface settings, Groove Studio, Looper, Arpeggiator, Patches, Backups and the app. Toggle category filters to combine them, or select **All**. Messages append in order for this page session and disappear on reload; changing filters never deletes history. The charcoal area briefly glows for new feedback and follows new entries only while you are at the bottom. Scroll inside it to read history. The logo, top MIDI controls and message area remain pinned when scrolling. The panel defaults to 100px tall; drag its bottom handle vertically (or focus it and use Up/Down arrows) to resize, with a 75px minimum. **x** dismisses it without deleting history; **Messages** beside Controller input reopens it. Only a new error reopens it automatically, revealing all categories so the error is visible; ordinary messages and warnings keep accumulating without reopening it. The same log stays accessible when a dialog is open. Field-validation errors remain beside their inputs; numeric progress/readouts and confirmation questions stay in their controls.
- **Help** beside the app version explains the app, playing and fader shortcuts, and its limitations; it replaces the former bottom Help panel. The CS mark opens reface CS information and reference links; the Yamaha mark opens Yamaha's website. Panel section and parameter labels open non-modal help windows near the clicked label, with content-sized width (minimum 500px, capped to the viewport) and height up to 90% of the viewport. About, Looper, Groove Studio, and Patch Manager help default to 900px wide, still capped to the viewport. The Patch Manager **Help** button beside **Save current sound** explains saving, organization, recall, INIT, audio, and backups in initially collapsed sections. Opening help closes existing help windows; **Alt-click** (or **Alt+Enter/Space** on a focused label) keeps them open. Drag a title bar to move a window, use the larger bottom-right handle to resize (or focus it and use arrow keys), and close it with **X** or Escape. Selecting a window brings it forward; hovering over it highlights the target that opened it. Hold **Alt** and scroll over a window to adjust its background opacity (20-100%); text stays opaque.
- **Connect MIDI** requests ordinary browser MIDI access and lists available ports. A unique port containing "reface" is selected automatically for each direction; correct the reface input and output selections if their names differ or are ambiguous. The controller input defaults to the reface input and can be changed independently; its last selection is restored if available. The green dot reports port availability, not verified hardware identity; detailed feedback, errors and warnings appear in Messages. An unavailable reface is reported as a warning without reopening dismissed Messages; connection errors still reopen it. The configurable connection action and pitch-range override can send settings to the synth.
- Supported panel controls send CC or pitch bend on the selected receive channel, or channel 1 when set to All; physical synth CC feedback updates the panel without echo. Enable MIDI Control on the synth; its status is reported when read. Master transpose, pitch-bend range and tempo use SysEx, so their first use requests extra browser permission. The tempo fader and arpeggiator share a 40–240 BPM range and send exact BPM values to the synth.
- When a reface MIDI connection becomes available, the app reads device settings and captures supported synth parameters over SysEx. Unsaved sound edits prompt for save or discard first; cancelling keeps them. Capture reflects the current sound, not necessarily the physical fader positions after a patch is loaded. Missing or invalid values are reported; expression, physical volume, octave, looper, and pitch-bend position cannot be captured. A synth tempo outside 40–240 BPM is reported and left unchanged. Hardware response behavior still needs verification.
- **Expression** sends CC 11 on the active receive channel, ranging from 0 to 127 (default/reset 127). On-screen notes use a fixed velocity of 100. Optionally enable position-sensitive expression for mouse/touch: each new key press sets expression and updates the fader, with the bottom 20% at 127. CC 11 affects all sounding notes on that channel, including held notes; it is not per-note volume. Synth and controller CC 11 feedback updates the fader without echoing synth input.
- The app transposes on-screen, external-controller, and arpeggiator notes; it also sets the synth's master transpose for its own keyboard. External-controller velocity is preserved; its channel is preserved when the receive channel is All. Synth notes are not echoed. Notes shifted outside the MIDI range are skipped and reported. Port changes release forwarded and on-screen notes where possible; send failures appear in MIDI status.
- A separate **Controller input** forwards pitch bend and CC messages unchanged, preserving their incoming channels when the receive channel is All; supported controls also update the panel without echo. Use MIDI Learn to remap individual controls. The compact row beneath the synth contains **MIDI Learn**, **Assignments**, **Clear assignment**, **Modulation value** and position-sensitive expression. Its buttons and assignment selector match the top MIDI toolbar. **Modulation value** always sends standard modulation-wheel CC 1 on the active receive channel (channel 1 when set to All) and follows incoming, unremapped CC 1 from the synth or controller; other CCs and patch capture do not change it. The obsolete wheel-target selector and its saved mapping are no longer used. Forwarded CCs may not all be supported by the synth. Active controller sustain is released on controller/output changes, MIDI Reset, or page hiding where possible.
- **MIDI Learn** assigns a separate controller's absolute CC knobs/sliders to on-screen synth faders, including selectors, pitch bend, transpose, octave, tempo and the browser looper. Select a separate Controller input, enable MIDI Learn beneath the synth, move an on-screen fader (drag/click, wheel or keyboard), then move the hardware control. The target glows amber; the assignment message is consumed without forwarding its original CC. Repeat for more faders, then turn Learn off; assignments stay active. Physical reface changes, notes, pitch-bend messages and controls outside the synth panel do not select or bind targets. Relative encoders and channel-mode CCs 120-127 are not learning sources; configure encoders for absolute CC mode.
- Learned controls use **pickup**: after a patch recall, another fader edit, reload or reconnection, move the hardware control to or across the current on-screen value before it takes over. Values scale across each fader's range, and output follows the normal synth routing, including the selected receive channel and SysEx requirements. Assignments are remembered per MIDI input port ID, incoming channel and CC in this browser only, excluded from patches, file exports and cloud backups. They are listed beneath the synth and removable with **Clear assignment**. Learning an already-mapped source replaces its old assignment; learning hardware CC 1 affects only that controller/channel, not the standard on-screen Modulation value slider. Clearing it restores unchanged CC 1 forwarding. Forwarded sustain previously held by a newly learned source is released. Learn mode itself is never restored, and port changes turn it off. A changed device port ID requires relearning.
- **MIDI Reset** stops drum/looper playback and clears arpeggiator held/latch notes without changing its ON, Latch, or Chord settings. It flushes queued MIDI, sends Sustain Off (CC 64) on all 16 channels, explicit Note Offs for tracked app/received reface notes, then All Notes Off (CC 123) and All Sound Off (CC 120) on all 16 channels to the selected output. The app's held-key state is cleared; release and replay keys held during reset. Both the drum Stop button (including Space-to-stop) and the looper fader's STOP position now perform this reset, even if already stopped or transport linking is unchecked. PAUSE does not perform a full reset. Queue-cancellation and send failures are reported; successful submission does not confirm the synth responded.
- Stopping finalizes elapsed recording time without playing overdue notes or starting a new playback pass at a recording boundary. The transport is marked stopped before held recordings are finalized, so shutdown does not generate fresh Note Ons.
- **Arpeggiator**, beside the YAMAHA logo, replaces on-screen and separate-controller notes with a pattern on the active receive channel while enabled; the reface's own keyboard remains direct-playing. Its ON button lights red when enabled, and Latch and Chord light amber when active. The output preserves each source note's velocity. Switch it off to resume notes still held. Its shared tempo resets to 120 BPM on activation or by double-clicking the display. Click −/+ for one BPM, Shift-click for ten, or use the wheel over the display (Alt for ten). Rate and Mode cycle on click; right-click, Arrow Down, or Shift+F10 opens their full menus. Rates run from 1/2 to 1/32 (default 1/16), with a 50% note gate. Up/down and down/up do not repeat turning points; first/last/middle alternates lowest and highest toward the center. Random repeats a note at most three times; a single-note pattern pauses for one step after three repeats.
- **Latch**, on by default, keeps playing after release and replaces the pattern on the first new key after all keys are released. **Chord** expands white keys into C-major diatonic triads (C major, D minor, E minor, F major, G major, A minor, B diminished); each black key plays the diatonic seventh chord rooted at the white key to its left (for example C-sharp plays Cmaj7). Notes above MIDI 127 are omitted. MIDI Reset, output changes, and hiding the page stop the pattern and clear held/latch state.
- **Phrase looper** runs in the browser independently of the synth's hardware looper. Select CLEAR, then REC to arm; the first note starts recording. The standby guide uses a short MIDI note and the synth's current sound; select CLEAR → PLAY → REC to skip it. Select PLAY to finish the first take and loop it, REC to overdub, and PLAY to finish overdubbing. PAUSE resumes from the paused position; STOP rewinds. CLEAR erases the phrase.
- Beneath the looper, click **4/4** to toggle 4/4 and 3/4, use **− / +** to set the bar length, and click the final value to cycle note-start quantization (0/off, 1, 2, 4, 8, 16, 32); right-click or use Arrow Down for the full menu. The default **4/4 − 0 + 0** retains manual looper behavior. A nonzero bar length counts down from the first note, then wraps into overdubbing until PLAY is selected. Selecting PLAY early starts the fixed-length loop immediately, leaving unrecorded space empty. The countdown repeats on each recording pass.
- Quantization moves recorded starts to the nearest note division, preserving each note's duration; live playing remains immediate, and quantized overdubs become audible on a subsequent loop. Settings changed during an existing phrase apply to the next new recording, not the current phrase. The 1,200-beat limit allows up to 300 bars in 4/4 or 400 in 3/4.
- For the same MIDI channel and pitch, an overdub at an existing start replaces its duration. A later start cuts the preceding note short, including across the loop boundary. All app-routed same-pitch retriggers, including overlapping local/controller input, send Note Off before Note On rather than stacking unmatched voices; releasing an interrupted note cannot cut the newer one. Different MIDI channels remain independent.
- The icons beside **LOOPER** open loop import/export, open the saved-loop library, or save named loops to this browser. Loading replaces an existing phrase only after confirmation and leaves the new phrase stopped. In the import/export dialog, **Import loop file** accepts native loop JSON and Standard MIDI Files; **Export loop** asks for a filename and offers native JSON or pure MIDI without requiring a MIDI connection. Unsaved loops offer current or last-saved state where available. Native JSON preserves the exact loop length; pure MIDI omits app-specific length metadata, rounds timing to 1/9,600 beat, and may not restore trailing silence. The browser chooses the download location. MIDI import supports beat-based type 0 and synchronized type 1, but not type 2 or SMPTE timing. It retains notes, channels and velocities, reports ignored non-note events, and applies supported initial tempo and meter. Other MIDI files loop to the next bar after the last note; older looper MIDI exports with exact-length metadata remain supported. Exporting during recording or overdubbing finalizes held and scheduled notes and stops the transport; cancelling does not.
- The looper records on-screen keys, the selected external controller and reface keyboard, or generated arpeggiator notes rather than their held input keys. The reface keyboard still plays directly; its transmitted note numbers are recorded unchanged. Only notes are recorded, not controller changes; playback uses the current synth sound and the shared tempo. Up to 2,000 notes and 1,200 beats (ten minutes at 120 BPM) fit in one temporary phrase. Record and Play LEDs show the local transport state and beat, not the hardware looper. The guide's pitch and duration are approximations, not verified hardware values.
- MIDI Reset, output loss/change, and hiding the page stop the looper and release its app-routed notes where possible; the phrase remains until CLEAR or page reload. MUTE silences looper playback while its timing continues. The synth's locally played keys cannot be controlled independently of MIDI playback.
- The arpeggiator's notes and chord readouts reflect currently held on-screen, reface, and selected-controller notes, not released latched notes or generated chord tones. The chord detector recognizes major, minor, augmented and diminished triads, and dominant, major and minor 7th, 9th and 11th chords, including inversions and extended chords with an omitted fifth. Major chords are green and minor chords blue; augmented, diminished and dominant chords remain neutral. It prefers a match rooted on the lowest held note; otherwise it selects one deterministic match. Other note combinations show no chord.
- Five read-only floating displays sit below the toolbar and above the synth: LFO, Filter, Amp ADSR, Filter ADSR, and Effect. Dark dotted grids and cyan curves update live with the faders, including resets. Cards wrap on smaller screens without covering the instrument. The gap to the case is reduced by 75%; a fully open filter shows a flat, vertically centered response.
- These are **schematic previews**, not measured audio or calibrated Hz/millisecond curves. Both envelopes share A/D/S/R, with illustrative linear influence from EG Balance; zero amplitude-envelope influence retains a note gate, not silence. LFO shows its destination and relative depth/speed; Effect switches between echo, modulation, and distortion/tone illustrations. See the MIDI reference for verified behavior and modeling limitations.
- Display numbers are white, while their labels retain muted colors. Display backgrounds stay dark in every mode. Focus Mode colors graph lines and their shaded fills to match the sections: LFO green, Filter peach, both ADSR displays blue, and Effect pink. Relative luminance and fill opacity are preserved; turning Focus Mode off restores cyan.
- The compact toolbar includes **Hide Displays**, which removes the cards and their reserved space without changing controls or other view modes. Hidden displays continue to follow faders; Reset faders preserves their visibility.
- Each display has a subtle **reset** button for its section only. LFO resets Assign/Depth/Speed; Filter resets Cutoff/Resonance; Effect resets Type/Depth/Rate. Both ADSR reset buttons perform the same action: restore EG Balance and all A/D/S/R faders. Other sections, mute restoration, pitch-bend range, and view modes are preserved.
- One SVG panel follows the supplied reface CS reference image, with 37 individually addressable keys (optionally 61), independent faders, OSC selector LEDs, and looper transport LEDs.
- The CS mark is a thin, connected SVG outline path based on the reference image, not font-rendered text.
- Hold a key with a mouse, touch, Space, or Enter to animate it. Release or move focus away to release keyboard-held keys.
- Play the middle octave with **A W S E D F T G Y H U J K**, chromatically C4 through C5 at default settings. Hold/release letters for chords; the same physical QWERTY keys stay mapped to the middle keys in both keyboard views. Ctrl/Alt/Meta shortcuts and typing in editable fields do not trigger notes.
- Focus Mode overlays the mapped letters and small gray note names at the tops of all visible keys. Note names also appear outside Focus Mode whenever transpose is nonzero. Names follow both Octave and Transpose (default ranges C3-C6 or C2-C7), while letters stay anchored. Changing octave, keyboard range, speaker layout, or fader travel releases locally held notes, as do reset, window blur, and page hiding.
- Drag a fader or focus it and use arrow keys; Shift+arrow and Page Up/Down make larger changes on continuous controls. Home moves to the top (maximum); End moves to the bottom (minimum), matching their positions on the keyboard. Hovering, keyboard focus, and dragging give the handle a brighter glow that eases in/out over 180 ms. Fader movement remains immediate. By user choice, this glow-only fade stays active with reduced motion; key and LED transitions still respect that preference.
- Hover a fader and scroll up/down to increase/decrease it by one step. Alt+wheel changes continuous faders by 10; selectors and Transpose always move one step. Shift+wheel keeps the normal single step; Shift+arrow keyboard shortcuts are unchanged. Wheel input updates graphs, readouts, LEDs, and mute handling without stealing focus. Vertical wheel scrolling is consumed only over faders, including at their limits; horizontal scrolling and Ctrl+wheel zoom remain available. Pitch Bend retains wheel adjustments like keyboard adjustments, without springing back.
- **Transpose**, between Pitch Bend and Expression, ranges from -12 to +12 semitones. It controls the synth's master transpose and shifts app-routed MIDI notes; held direct notes are released at their original pitch.
- **- 12 +** beneath Pitch Bend controls the magnitude of the synth's bend range from 0 to 24 semitones, preserving its direction. If direction is unknown, the app offers to read it; if that fails, choose normal or inverted before sending. With no device connected the value is saved locally, not sent. After connecting, read the direction and confirm before restoring a saved range. Reset faders requests 12 using the same safeguards; a zero range has no readable direction.
- Double-click any fader's handle or track, or press Delete while it is focused, to restore just that fader to its Reset position without changing other controls or view modes. Both actions end any active drag on that fader.
- **MUTE** releases app-routed notes and suppresses new ones without changing expression; the arpeggiator keeps its timing. It cannot mute notes played directly on the synth. Reset clears mute state.
- Clickable selector labels and MUTE/UNMUTE have the same 180 ms fading hover glow as fader handles, including when reduced motion is enabled.
- Octave, Looper, LFO Assign, OSC Type, and Effect Type have one horizontal track line per labeled position, aligned in both travel sizes. Click a position label to select that exact step and refresh its LEDs/readout, without dragging. Repeated label clicks keep selecting that step rather than resetting it. Continuous faders retain their finer scales.
- The **2x fader travel** toggle doubles the control travel and expands the case/panel, keeping key dimensions, fader handles, labels, and values unchanged.
- **5 Octaves** adds one octave below and above the original keyboard (61 keys instead of 37). Keys narrow horizontally to fit the same frame; heights, controls, and Octave/Transpose values stay unchanged. Toggling releases held keys. This works with all view modes, and Reset faders preserves the keyboard view.
- **Hide Speakers** removes the speaker/end margins and narrows the case without resizing keys or controls. Both ends remain clickable (slim strips when compact): left lowers the Octave selector one step, right raises it, bounded at -2/+2. Enter/Space also activate focused ends. This works with Focus Mode and normal/2x travel; Reset preserves the selected layout.
- **Focus Mode** adds subtle section colors and colors the Cutoff handle red and Resonance handle blue. The Looper, Pitch Bend, Expression, and Octave retain their appearance. Live gray numbers show fader values; hover tooltips include CC numbers where available.
- **Reset faders** restores starting positions, including expression 127, centered octave/pitch bend, maximum cutoff/decay/sustain, and other faders at the bottom. Resets send supported values to the synth; page load itself does not.
- Only the selected OSC type's LED glows: SAW red, PULSE orange, SYNC yellow, RING lime, FM light blue. Other OSC LEDs are black. The dots sit to the right of the labels, with clearance before the Texture fader.
- On smaller screens the panel scrolls horizontally to keep controls usable.
- Focus Mode, hidden speakers and displays, five-octave view, fader travel and position-sensitive expression are remembered in this browser. Storage errors are displayed and defaults are used when preferences cannot be restored.

### Device settings

**Device settings** in the top toolbar provides a separate view of documented reface CS system settings and tone-generator volume. Connecting MIDI attempts a non-blocking read, which may request separate SysEx permission; **Read settings** retries. Missing or invalid replies remain unknown. Editable values are drafts until **Apply changes**, which sends only changes and requests read-back. Individual results distinguish confirmed values from failed or unconfirmed sends; a sent message alone does not establish hardware state.

The synth panel offers immediate transmit/receive channel, Local Control and speaker controls. Click a channel to cycle, or right-click for a menu; `?` indicates an assumed or unconfirmed value. Without a read, channel 1 transmit, All receive and both switches On are assumed. Controls are disabled without an output. A specific receive channel routes outgoing notes and controls to it; All uses channel 1 for app-generated messages while preserving forwarded and recorded channels. Changing receive channel stops the looper, arpeggiator notes and drums before sending. Synth input is accepted on all channels.

The dialog also offers MIDI Control, Auto Power-Off, Master Tune, pitch-bend direction and magnitude, and MIDI tone-generator volume. Pedal settings are experimental: although listed in the CS Data List, their behavior on actual CS hardware is unverified. Channel and switch changes may interrupt sound or communication, and disabling transmit can prevent read-back.

**Reset** prepares only verified factory defaults in the form and lists settings whose defaults were left unchanged; it does not send anything until Apply. It is not a hardware factory reset. The dialog links to the owner's keyboard-setting and LED confirmation diagrams, and describes the destructive hardware factory-reset procedure. Device values and pending edits are cleared when the selected MIDI connection changes. Device settings are not included in browser backups or automatically applied from browser storage. SysEx messages and device responses require hardware verification.

## Groove studio

The collapsible **Groove studio** sits directly below the synth and above the Patch Manager. Its first instrument is an 808-inspired, sample-free Web Audio drum machine, not a faithful circuit emulation. Kick and toms use pitched sine oscillators; filtered noise supplies snares, hats, shaker, clap, cymbals and attack components.

- **Help** in the Groove Studio header opens a detailed guide without expanding the studio itself. The introduction explains its sixteenth-note step sequencer and internal/external MIDI operation; all later sections start collapsed and can be expanded independently.
- Four lanes start empty: kick, snare, closed hi-hat, and open hi-hat. Add missing instruments, including three toms, shaker, clap, crash and ride cymbals. Each subtly colored lane has an instrument preview, Solo, Mute and **…** for removal, tone controls and tone import/export. Closed hats choke open hats.
- Each lane has **S** (solo) and **M** (mute) toggles. When any lane is soloed, only soloed, unmuted lanes sound; mute takes priority over solo. These controls affect sequenced hits, MIDI triggering and lane previews, and immediately silence excluded voices without erasing steps. Tone-picker previews ignore solo and mute.
- Each pattern has 1–16 bars of sixteenth notes in a horizontally scrolling grid: 16 steps per bar in 4/4 or 12 in 3/4. Shortened bars and steps 13–16 in 3/4 are preserved but not played. The drum machine's time-signature selector and looper meter update each other. Clicking an empty step sets velocity level 5; subsequent clicks bounce **5, 4, 3, 2, 1, 2, 3, 4, 5...**. Tooltips include the exact MIDI velocity. Right-click or Delete/Backspace clears the focused step.
- Each bar has Copy, Paste and Clear icons. Copy and Clear apply to soloed lanes, or all lanes when none are soloed; Clear immediately clears visible steps. Paste immediately replaces only copied instrument lanes and adds missing lanes with default tones. Only steps visible in both the copied and current meter are pasted, leaving hidden steps unchanged. The copied bar remains available until the page is reloaded.
- Named patterns, bar lengths, lanes, steps, solo/mute states, and voice settings save automatically in this browser, separately from reface patches. **New pattern** starts empty with the four default lanes; **Save pattern as** duplicates the current pattern. Select a pattern to load it, or rename/delete it. Switching patterns applies to subsequent scheduled hits, not a queued song arrangement. Shared tempo and meter remain transport settings rather than per-pattern settings.
- A lane's **…** controls include Level, Tune, Decay and Tone. Save appears when these differ from the loaded tone or instrument defaults; save a named variation or overwrite an existing one. The selected tone's name appears beside the lane actions and opens the same picker as Load. Load shows only that instrument's tones, with name filtering, favorites, sorting and independent previews. Loading over modified settings offers to save or discard them first. Patterns keep their own tone snapshots even if a saved tone is changed or deleted. Import/export transfers individual tone JSON files; Groove Studio and all-section backups include the tone library. Older pattern and backup files remain importable.
- In **External MIDI**-only mode, lane options show **Level** but hide Tune, Decay, Tone, the tone name, and tone Save/Load/Import/Export actions. Lane preview, solo/mute and removal remain available. Switching back to Internal or Internal + MIDI restores the controls without changing saved tones or lane settings.
- **Export pattern** asks for a filename and exports versioned JSON or pure MIDI. MIDI has a track per lane on channel 10, including muted and non-soloed lanes; it omits tone settings, mute/solo and hidden 3/4 steps. **Import pattern** validates JSON and loads it with playback stopped.
- Click **Enable audio** beside Audio output, **Connect MIDI**, the green play icon, or a voice's preview button to unlock audio. Play automatically enables audio before starting; MIDI connection proceeds even if audio enabling fails. MIDI messages alone cannot unlock browser audio. The white square stops playback. Space toggles drum play/stop, including when a drum step or transport button is focused; editable fields, dialogs, existing synth-key shortcuts, and buttons outside Groove studio retain their normal keyboard behavior. The master level, linked-transport choice, and MIDI offset are also remembered locally. Collapsing the panel does not stop playback; page hiding and MIDI Reset stop drums.
- Hover over the drum tempo input or master slider and scroll to change its value by one; Alt+wheel changes it by ten. Tempo changes immediately synchronize with the synth tempo fader, arpeggiator, and looper. Ctrl+wheel and predominantly horizontal scrolling are left to the browser.
- **Start on keypress** starts stopped drums on the first melodic Note On from the on-screen keyboard or either selected MIDI input, and keeps playing after release. Channel-10 controller drums, calibration notes and generated looper/arpeggiator notes do not trigger it. The linked-transport checkbox determines whether the looper starts too. This choice is remembered only in this browser. Browser audio still needs to have been unlocked by a click or key gesture. The arpeggiator uses the same absolute beat grid as Groove Studio; it joins the next rate subdivision when another transport is running, rather than starting an independent timer phase.
- MIDI notes on **channel 10 of the selected Controller input** trigger drums according to Drum output, even if that input is also the reface input. Incoming velocity is preserved before lane Level is applied. These channel-10 messages are consumed rather than routed through the melodic reface path, transposed, arpeggiated, highlighted as melodic notes, or recorded by the melodic looper. Note-offs do not truncate internal percussion tails; channel-10 CC 120/123 silence drums and stop their sequence. Removing a lane removes its sequence; MIDI can still trigger that instrument with default settings. Other MIDI channels retain their existing melodic routing.
- **Drum output** selects internal audio, external MIDI, or both for patterns, lane previews and controller-triggered drums. MIDI settings chooses an independent output and channel (default 10), with editable MIDI notes for all lanes. In **Internal + MIDI**, the looper MIDI offset also shifts sequenced external drums; in **External MIDI**, external drums ignore it. Live previews and controller hits stay immediate in both modes. Lane **Level** scales external velocity too; zero sends no hit. Other internal tone controls and the internal master volume do not affect external sounds. MIDI uses browser timers and can jitter under load; very late notes are skipped. Playback continues to require Web Audio for the shared clock, even in MIDI-only mode. Tone-picker previews remain internal.
- MIDI settings offers CS2x XG kits and its six preset drum Performances, preset/user Performance banks, and custom bank/program values. Choosing a CS2x XG/SFX kit automatically selects channel **10**; choosing a Performance selects channel **1**. A later manual channel override is retained until another preset is chosen. XG kits require a suitably configured CS2x Multi part; Performances require Performance mode and matching layer receive channels. Selecting a preset sends bank/program changes; custom values require **Apply kit / Performance**. The chosen sound appears beside **MIDI settings**. The inline **Reverb** slider sends CC91 (0–127) to the selected external output/channel. These messages can replace the current sound and may reset device settings for that part. The app does not change modes or reapply sounds/reverb on reconnect. Generic devices must support the selected bank/program convention. MIDI program fields use 1–128.
- Routing, output, channel, kit, reverb-slider value and lane mappings are browser-local preferences, excluded from exports and cloud backups. The default mapping is shared globally, with separate mappings for each selected CS2x Performance. MIDI sends do not confirm hardware response. Stopping, changing routing/sound settings, hiding the page or losing the output cancels pending drum events and releases tracked notes where possible. Avoid sharing the same output, channel and notes with other MIDI sources, because a MIDI note-off can affect them.
- **Octave** beside MIDI settings shifts all external drum notes by -3 to +3 octaves (12 semitones each; default 0), including patterns, previews and controller hits. It leaves base lane-note numbers and internal audio unchanged, and is remembered with the mapping: shared for standard/XG kits, separate for each CS2x Performance. Changing it releases old external notes and replaces queued hits without stopping playback. Notes shifted outside MIDI 0-127 are skipped with a warning rather than clamped or wrapped. Older preferences default to zero shift.
- Standalone software can receive external drums through a virtual MIDI cable such as [loopMIDI](https://www.tobias-erichsen.de/software/loopmidi.html): select that port as Groove Studio output and as the standalone synth's MIDI input, match channels, and choose a drum sound in that synth. No DAW is needed if the synth runs standalone. CS2x presets are device-specific, not universal software-synth patches. A separate USB–MIDI adapter successfully triggered the CS2x in hardware testing; the tested reface setup did not forward computer USB MIDI through its DIN MIDI OUT. Physical timing and instrument-specific effects still require hardware verification.

### Playback timing and audio output

- Drums and looper share tempo and the musical bar grid. **Start and Stop together with looper** links starts in both directions; pausing or clearing the looper also stops linked drums, including when you select an already-selected Pause position. Uncheck it for independent starts and pause/clear behavior. As a hanging-note safety measure, an explicit Stop always stops both transports and performs MIDI Reset, regardless of linking. An empty looper still needs a recorded/imported phrase to play. Recording remains armed until the first melodic note, as before; for drum-aligned loop boundaries, use a fixed bar length and play the first note on the intended downbeat.
- After drum audio is enabled, looper playback uses ahead-of-time, timestamped Web MIDI scheduling. Drums are scheduled on the Web Audio clock, mapped to the same audible timeline. A newly started player joins an already running player's next available bar; a short startup lead-in gives audio and early MIDI time to be scheduled. Existing looper recording, overdubbing, pause, mute, and MIDI import/export remain available. Arbitrary manual loop lengths still repeat at their recorded lengths, rather than being stretched to whole drum bars.
- **Looper MIDI offset** ranges from -600 to +600 ms: negative sends playback MIDI earlier than the drum beat, positive sends it later. Live keyboard/controller playing is not delayed. Align a short reface sound against a repeating drum hit by ear, using the actual monitoring path. Audio timestamps account for browser-reported output timing where available, but this is not automatic measurement of the complete MIDI/hardware/monitoring path, and a fixed offset cannot eliminate jitter. Changes cannot recall audio already handed to the device.
- **Calibrate MIDI offset** opens a calibration dialog. If MIDI input is unavailable or audio cannot start, the dialog displays the reason instead of silently returning or disappearing; close it, resolve the connection/audio issue, and retry. With an available reface input, calibration stops normal drum and looper playback and plays a standalone kick at exactly 100 BPM, without changing the saved pattern or shared tempo. Play notes on the selected **reface input** for as long as needed. Each nonzero-velocity Note On replaces the previous measurement with the elapsed time from the most recent test kick's scheduled playback time to the MIDI event's receive timestamp, not the earlier look-ahead scheduling call. **Done** applies only the latest delay positively (80 ms becomes +80 ms); there is no averaging, sign inversion, or nearest-beat rounding. Notes before the first kick and other MIDI inputs are not valid samples. **Cancel**, Escape, input loss, page hiding, and MIDI Reset leave the previous offset unchanged. Normal transports remain stopped after the test. This is a playing/input-delay alignment aid, not measurement of the reface's audio-output latency; no audio capture or microphone permission is needed.
- **Audio output** selects the drum engine's device where `AudioContext.setSinkId()` is available. **Choose audio output** appears when supported and requests device-selection permission; **Refresh outputs** refreshes the available list. No microphone permission is requested for drum playback. Unsupported selection, permission failures, device-list changes, suspended audio, and storage/send errors are shown in the panel. This selector does not reroute the reface's physical audio or patch MP3 previews.
- Web Audio requests interactive latency but does **not** expose ASIO drivers or guarantee a particular latency. Wired outputs are recommended; Bluetooth adds delay. Physical reface timing, audio-interface behavior, and final compensation still require checking on the actual hardware.

A piano-roll reface sequencer, fader automation, and a saw/square softsynth are future additions.

## Patch Manager

- Save the current on-screen sound controls as a named patch. Snapshots include the visible LFO, oscillator (including Portamento), Filter, EG, and Effects controls; they do not read back hardware state or include performance/system settings.
- Patch cards show the name, main category, tags, and a small line-and-handle outline of their LFO-through-Effects faders. **Detailed snapshots** shows descriptions and the original labeled control previews; its tooltip explains the view. Cards are listed below the synth, up to 500 px wide, in a responsive grid, with a hollow/yellow favorite star just left of Load in the top-right corner. Edit opens patch details; play, move, remove, and delete actions use icons with accessible names and tooltips.
- Filter by favorites, case-insensitive name substring, and any number of category/tag chips. No chips selected means no restriction; selections match any category and any tag, while the filter groups combine with AND. Clear filters resets all selections. Each patch still has one main category.
- Starter categories are pads, bass, plucks, keys, synth, FM, noise, FX, and Percussion; custom categories and tags are supported. **Manage categories / tags** can delete unused categories (including starter categories) persistently. Deleting a tag asks for confirmation and removes it from every patch.
- Each patch can have up to three MP3 attachments. Select a card to preview its first attachment; choose another track, reorder tracks with drag-and-drop or the move buttons, or remove an attachment. If browser autoplay policy blocks playback, use the displayed Play preview button. Adding files uses the browser file picker.
- Settings can hide audio attachments on patch cards; an arrow reveals or hides each card's tracks. Revealed cards stay open until closed or the page reloads.
- **Record** first loads the patch into the panel and sends all sound-control CC values to the synth. Recording opens only if every value is sent successfully; unavailable MIDI and partial send failures block it with an explanation. MIDI send success does not confirm the hardware applied the patch. Audio-input selection remembers your last choice across page reloads. If that input is unavailable, a warning appears and the default input is selected. Start recording and stop manually, or let it stop at 10 seconds; preview the locally encoded **256 kbps MP3** before saving it as an attachment, or discard it. Stereo is requested: two captured channels remain stereo, while a single captured channel stays mono. Existing attachments are unchanged. Requires microphone permission and HTTPS or localhost. Connect the synth's audio output to an audio interface: its USB MIDI connection does not carry audio. Recording stays local unless you explicitly save a cloud backup; the three-attachment limit also applies to recordings.
- After selecting a card, Left/Right selects the previous/next name-sorted patch in the filtered results and previews its first attachment without loading the synth. Navigation stops at the ends; typing, dialogs, and synth-control arrow shortcuts are unaffected.
- Load explicitly to apply the patch to the panel and send its CC values to the selected MIDI output. Without MIDI output, the patch still loads locally and reports that it was not sent. Send failures are reported as partial recall; MIDI Control must be enabled on the synth, and MIDI send success does not confirm the synth applied the values.
- The display beside the CS logo shows the loaded patch and a colored dot when browser-known sound controls differ from the saved patch. Long names scroll after five seconds and show their full name in the tooltip. The arrow buttons load the previous or next patch in the current library filters without wrapping; when the current patch is outside the filtered list, they start at the corresponding end. The **\*** button starts an INIT sound by resetting only patch controls, after protecting unsaved changes; the save icon and **Save current sound** offer overwrite or Save as for a loaded patch. Saving INIT opens the new-patch editor; replacing an existing name requires confirmation. After a reload, no patch is loaded automatically.
- Loading or reloading a patch with unsaved sound changes offers Cancel, Discard and load, Overwrite and load, or Save as and load. The optional **Ignore unsaved Synth state when loading patch** setting skips this protection for patch loads, including automatic loads and recording; INIT and synth capture still protect unsaved changes. Overwrite is unavailable without a saved active patch; saving changed controls over a patch with audio offers to keep or delete its audio. Save as prepopulates metadata without copying audio. Deleting the loaded patch retains its name as an unsaved sound. Tracking reflects only controls known to the browser, not unreported hardware changes.
- Patch data and audio are stored in IndexedDB for the current browser profile and origin. Use the top **Import / Export** dialog for a Patch Manager ZIP containing both patch metadata and MP3 files. Imports merge into the current library. Save/rename conflicts and deletion also require confirmation.
- Individual patch cards export a ZIP, and each MP3 attachment can be exported separately with an editable filename. Exporting an edited active patch offers the current sound, the saved sound, or cancellation. Importing a single patch recalls it unless unsaved-change protection is enabled and replacement is declined; browser state cannot confirm unreported hardware changes.

## Browser backups

The information box above the synth explains browser storage, file backups, and Google Drive. Close it or reopen it with the **?** button beside Import / Export; its visibility is remembered only in this browser.

**Import / Export** exports Looper, Groove Studio, Patch Manager, or all three as a versioned ZIP and closes after success. Imports merge saved items; identical matches need no conflict decision, while differing matches offer Overwrite, Ignore, or Create new with an editable unique name. Comparison includes visible metadata and audio bytes but ignores IDs and timestamps. Backups exclude browser preferences; unknown sections or versions are rejected. Patch audio is included in the archive. Browser storage is tied to the current origin and profile and may be cleared, so keep downloaded backups separately.

**Google Drive backups**, inside Import / Export, saves named, dated snapshots of all three libraries to a visible `refaceCS` folder. Audio is stored as separate files and checked on restore. Each backup uploads its own audio copies; a failed upload can leave unreferenced files in the folder. Select a version to merge or replace browser libraries; replacement first saves a recovery snapshot to Drive. Restore applies the three libraries separately, so a storage error can leave a partial restore; the recovery snapshot remains available. Avoid editing while saving or restoring. These are manual backups, not automatic sync; deletions do not propagate between devices.

To connect, follow the expandable setup instructions in the Google Drive backups dialog: enable the Google Drive API in a Google Cloud project, configure its OAuth consent screen and `drive.file` scope, and create a web application OAuth client with each app origin as an authorized JavaScript origin. Add your Google account as a test user if the consent screen is in testing mode. Enter the client ID in the app and use the same client ID and Google account on each device; do not enter a client secret. The client ID is saved locally; access tokens are held only in memory and may require reconnecting after reload or expiry. The app requests the `drive.file` scope, not access to all Drive files. Backups consume Drive storage and may contain private sounds and recordings.

## Goals
- MVP: a local browser app that visually controls the reface CS and sends MIDI CC in real time
- Mirror physical control changes when the synth sends MIDI feedback
- Save, organize, preview, export, and recall app-side patches (the synth itself has no patch storage)
- Later: basic MIDI sequencer, settings, and additional live-play features
